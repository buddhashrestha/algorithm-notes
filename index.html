Search range: first True, then last True

Find the first and last index of target in a nondecreasing array, including empty arrays and duplicate runs.

Reuse the existing inclusive boundary framework twice, rather than inventing a duplicate search.

Search only inclusive [l,r], with ans=-1 until a qualifying midpoint is seen. First search: nums[m]>=target is False...True, save m and move r left. Last search: nums[m]<=target is True...False, save m and move l right.

How to use it

  1. Find first True for nums[m]>=target with l<=r and ans=-1.
  2. If first is -1 or nums[first]!=target, return [-1,-1].
  3. Reset bounds and ans; find last True for nums[m]<=target.

Walk through an example

[1,2,2,2,4], target=2: first (l,r,m,ans): (0,4,2,2)->(0,1,0,2)->(1,1,1,1). Last: (0,4,2,2)->(3,4,3,3)->(4,4,4,3). Result [1,3].

The first >= boundary finds the first possible occurrence; equality verification rules out an absent target. Once the target exists, the last <= boundary gives the final occurrence. Both searches use exactly the framework above.

Watch for: First >= can land on a larger value, so verify equality before searching the last boundary. A last <= candidate alone can be smaller than target. Do not mix inclusive bounds with half-open updates.

Complexity: n array items: O(log(n+1)) comparisons for nonempty input, O(1) for empty; O(1) auxiliary space. Each iteration discards at least half the candidate interval up to rounding. Index arithmetic and value comparisons assumed O(1); sortedness is a precondition, not checked with an O(n) scan.

Practice the same idea

Change >= to > to find first strictly greater; change <= to < to find last strictly smaller. Keep the direction of the True region matched to the boundary update. bisect_left/right encode related insertion positions, but use this existing ans=-1 framework here.

def searchRange(nums, target):
    l, r, ans = 0, len(nums) - 1, -1
    while l <= r:
        m = l + (r - l) // 2
        if nums[m] >= target:
            ans = m
            r = m - 1
        else:
            l = m + 1
    first = ans
    if first == -1 or nums[first] != target:
        return [-1, -1]
    l, r, ans = 0, len(nums) - 1, -1
    while l <= r:
        m = l + (r - l) // 2
        if nums[m] <= target:
            ans = m
            l = m + 1
        else:
            r = m - 1
    return [first, ans]

Algorithm 02

Backtracking

Build one candidate step by step. Explore each valid choice, then undo it so the next branch starts clean.

How to think Framework Visualize Decisions Problem map Solutions Tree maze

How to think inside dfs

Focus on one call, not the entire recursion tree.

dfs(state, path)

path is what you have built. state tells you where you are and which choices remain.

  • 1
    Stop

    If path is complete, save path.copy() and return.

  • 2
    Choose and explore

    Add one valid choice, update state, and recurse.

  • 3
    Undo

    Remove the choice so the next branch starts from the same path.

Concrete example

dfs(1, [1]) means: "I chose 1. Now decide whether to take or skip nums[1]."

One framework

Each problem changes the state, choices, completion rule, and pruning rule.

Universal backtracking template
res = []

def backtrack(state, path):
    if complete(state, path):
        res.append(path.copy())
        return

    for choice in choices(state, path):
        if not valid(choice, state, path):
            continue

        path.append(choice)                    # choose
        next_state = apply(choice, state)

        backtrack(next_state, path)             # explore

        undo(choice, state)                    # if state is mutable
        path.pop()                             # undo path

backtrack(initial_state, [])
return res

Keep the first successful root-to-leaf path

Find one root-to-leaf route through a proper binary tree whose value-0 nodes are blocked.

Write a breadcrumb when entering; erase it only if that branch fails.

On entry, path contains the unblocked ancestors of the candidate node. A False return restores exactly that incoming path; a True return preserves the complete successful root-to-leaf path. A leaf has no children in the original tree, not merely no unblocked children.

The reusable pattern

Pattern template · adapt names and helpers to the problem
def search(node, path):
    if node is None or node.val == 0:
        return False
    path.append(node.val)
    if node.left is None and node.right is None:
        return True
    if search(node.left, path) or search(node.right, path):
        return True
    path.pop()  # Only a failed branch is undone.
    return False

How to use it

  1. Reject None or value 0 without changing path; otherwise append the node's value.
  2. Return True at an original leaf or if a left/right recursive call succeeds, preserving the successful path.
  3. If both branches fail, pop this node and return False; a proper tree needs no visited set.

Walk through an example

       1
      / \
     2   3
    /   / \
   0   0   4
[] -> [1] -> [1,2]; blocked 0, missing child -> pop 2.
[1] -> [1,3]; blocked 0 -> [1,3,4]; leaf -> keep path.
Result: [1, 3, 4].

Watch for: Unconditionally popping after success erases the answer. A node whose children are blocked is not a leaf. No visited set is needed only because this is a proper tree; a graph may have cycles or shared nodes and requires visited-state handling.

Complexity: For n tree nodes and node-height h, worst-case time is O(n), recursive stack space O(h), and the retained path uses O(h) space. Search stops after the first successful leaf. Highly skewed trees may exceed Python's recursion limit.

Practice the same idea

Unlike enumerating subsets or permutations, this is a find-one search: failure rolls back, success deliberately commits the path. Duplicate node values are fine for existence, but store node references if route identity matters.

class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        res = []
        used = [False] * len(nums)

        def backtrack(path):
            if len(path) == len(nums):
                res.append(path.copy())
                return

            for i in range(len(nums)):
                if used[i]:
                    continue

                path.append(nums[i])
                used[i] = True
                backtrack(path)
                used[i] = False
                path.pop()

        backtrack([])
        return res

class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        res = []

        def backtrack(open_count, close_count, path):
            if open_count == close_count == n:
                res.append("".join(path))
                return

            if open_count < n:
                path.append("(")
                backtrack(open_count + 1, close_count, path)
                path.pop()

            if close_count < open_count:
                path.append(")")
                backtrack(open_count, close_count + 1, path)
                path.pop()

        backtrack(0, 0, [])
        return res

Kadane: best ending here, best anywhere

Find the maximum sum of a nonempty contiguous subarray, including all-negative input.

At each value, choose exactly one: extend the previous segment or start fresh.

After processing index i, ending is the best nonempty sum ending exactly at i; best is the best nonempty sum anywhere in [0, i].

The reusable pattern

Pattern template · adapt names and helpers to the problem
ending = best = nums[0]  # Nonempty input.
for i in range(1, len(nums)):
    ending = max(nums[i], ending + nums[i])
    best = max(best, ending)
# ending: best ending HERE
# best: best found ANYWHERE

How to use it

  1. Reject empty input; initialize both states from the first value.
  2. Set ending = max(value, ending + value).
  3. Set best = max(best, ending).

Walk through an example

value:   -4   3  -1   4  -7   2
ending:  -4   3   2   6  -1   2
best:    -4   3   3   6   6   6
winner:       [3, -1, 4] -> 6

A nonempty segment ending at the current value has only two possibilities: it starts here, or it extends a segment ending at the previous value. Keeping the better of those two is enough. A separate best records winners that ended earlier.

Watch for: Initializing best to zero silently permits an empty subarray and gives the wrong answer for all-negative input. Updating only ending also loses an earlier winner.

Complexity: Let n be the input length. O(n) time and O(1) auxiliary integer variables, excluding input and printed output. These are unit-cost arithmetic bounds: if intermediate sums have at most B bits, additions/comparisons can take O(B) and the states use O(B) bits. No values[1:] slice is created.

Practice the same idea

Separate 'best ending in this state' from 'best seen globally' in streaming dynamic programming, such as longest valid runs.

Prefix sums: subtract boundaries, count earlier partners

Answer many static range-sum queries or count nonempty subarrays whose sum equals a target.

A subarray sum is the difference between two prefix boundaries, even with negative values.

P[0] = 0 and P[r] is the sum of values[0:r], so sum(values[l:r]) = P[r] - P[l]. Before counting boundary r, frequency holds exactly the earlier prefixes P[0:r].

The reusable pattern

Pattern template · adapt names and helpers to the problem
prefix = [0]
for value in nums:
    prefix.append(prefix[-1] + value)

# Sum of nums[left:right]; right is excluded.
answer = prefix[right] - prefix[left]

How to use it

  1. Build P from a leading zero by adding each value.
  2. For [l, r), subtract P[l] from P[r].
  3. For counting, look up P[r]-target before storing P[r].

Walk through an example

values:        2  -2   3  -1   2
boundary:  0   1   2   3   4   5
P:         0   2   0   3   2   4
[1,4): P[4]-P[1] = 2-2 = 0
target 2, matches added: 1, 0, 0, 2, 2 -> 5

Both prefixes start at index zero. Subtracting the prefix before left cancels everything before the desired range. Keeping frequencies of earlier prefixes extends the same identity to counting matching subarrays, even when values are negative.

Watch for: Store the current prefix only after lookup, or target zero counts an empty subarray. Store frequencies, not a set: duplicate prefixes represent distinct starting boundaries. Ordinary sum-based sliding windows are not reliable with signed values.

Complexity: Let n be the input length. Prefix construction is O(n) time and O(n) integer storage; each validated range query is O(1). Counting is expected O(n) time and O(n) stored prefixes, but can be O(n^2) with pathological dictionary collisions. Excludes printing. Bounds assume unit-cost integer arithmetic and hashing; Python sums, target differences, and counts can grow in bit length, increasing arithmetic, hash, and storage costs.

def prefixes(values):
    prefix = [0]
    for value in values:
        prefix.append(prefix[-1] + value)
    return prefix

def range_sum(prefix, left, right):
    if not 0 <= left <= right < len(prefix):
        raise IndexError('invalid half-open range')
    return prefix[right] - prefix[left]

def count_sum(values, target):
    frequency = {0: 1}
    total = answer = 0
    for value in values:
        total += value
        answer += frequency.get(total - target, 0)

Hash maps: choose a bucket, then check equality

Use this small separate-chaining model to understand collisions, replacement, deletion, and growth; use Python dict for real applications.

Two keys can share a hash without being the same key.

Each live key appears once in bucket hash(key) % bucket_count; size counts entries, not occupied buckets. Equal keys must have equal stable hashes, but equal hashes do not imply equal keys. The frozen test keys deliberately all hash to 1.

The reusable pattern

Pattern template · adapt names and helpers to the problem
index = hash(key) % len(buckets)
for stored_key, value in buckets[index]:
    if stored_key == key:
        return value
# Same bucket does not mean same key.
raise KeyError(key)

How to use it

  1. Choose a bucket and scan its entries using key equality.
  2. Replace an equal key, delete its entry, or add one new entry.
  3. Before exceeding load 1, double buckets and redistribute every entry.

Walk through an example

buckets 2:  0: []  1: [(1,10), (2,20)]
insert 3 -> buckets 4, all hashes still 1:
            0: []  1: [(1,10), (2,20), (3,30)]
replace 2:         [(1,10), (2,200), (3,30)]
delete 1:          [(2,200), (3,30)]

Watch for: Resizing changes the bucket modulus, so entries must be redistributed. Replacement must not increment size. Do not use hash equality as key equality or assume growth fixes identical hashes. This toy is not CPython dict's implementation.

Complexity: Let n be live entries and B the bucket count. Assuming well-distributed hashes, constant-time hash/equality/index arithmetic, and bounded load, lookup/deletion are expected O(1) and insertion is expected amortized O(1). Any single operation can take O(n+1) worst-case; growth costs O(n+B) and occurs when n=B. Direct redistribution avoids equality scans during rehash. Storage is O(n+B), with O(n+B) extra during growth. There is no shrinking: B reflects peak size, not current n. Excludes printing and key/value object storage. Python integer hashing/equality/arithmetic may depend on operand bit length. Our constant-hash test intentionally demonstrates the O(n) collision case, not the average case.

from dataclasses import dataclass

@dataclass(frozen=True)
class Key:
    number: int

    def __hash__(self):
        return 1  # Deliberate collisions, stable across runs.

class ChainedMap:
    def __init__(self):
        self.buckets = [[], []]
        self.size = 0

    def _bucket(self, key):
        return self.buckets[hash(key) % len(self.buckets)]

    def _grow(self):
        old = self.buckets
        self.buckets = [[] for _ in range(2 * len(old))]
        for bucket in old:
            for key, value in bucket:
                self._bucket(key).append((key, value))

    def put(self, key, value):
        bucket = self._bucket(key)
        for i, (stored, _) in enumerate(bucket):
            if stored == key:
                bucket[i] = (stored, value)
                return
        if self.size == len(self.buckets):
            self._grow()
            bucket = self._bucket(key)
        bucket.append((key, value))
        self.size += 1

    def get(self, key):
        for stored, value in self._bucket(key):
            if stored == key:
                return value
        raise KeyError(key)

    def delete(self, key):
        bucket = self._bucket(key)
        for i, (stored, value) in enumerate(bucket):
            if stored == key:
                del bucket[i]
                self.size -= 1
                return value
        raise KeyError(key)

    node.prev, node.next = anchor, right

  1. Enqueue with append(value) on the right.
  2. If the queue is nonempty, dequeue with popleft().

popleft:     returns 7; [8]
append 9:    front [8, 9] back

Every recursive call hands back the branch that should occupy its old socket.

    value: object
    left: object = None

class BSTMap:
    def __init__(self):
        self.root = None

    def put(self, key, value):
        def place(node):
            if node is None:
                return Entry(key, value)
            if key < node.key:
                node.left = place(node.left)
            elif key > node.key:
                node.right = place(node.right)
            else:
                node.value = value
            return node
        self.root = place(self.root)

    def get(self, key):
        node = self.root
        while node is not None:
            if key == node.key:
                return node.value
            node = node.left if key < node.key else node.right
        raise KeyError(key)

    def items(self, lo, hi):
        if lo >= hi:
            return
        node, stack = self.root, []
        while node is not None or stack:
            while node is not None:
                if node.key < lo:
                    node = node.right
                else:
                    stack.append(node)
                    node = node.left
            if not stack:
                break
            node = stack.pop()
            if node.key >= hi:
                break
            yield node.key, node.value
            node = node.right

class Trie:
    def __init__(self):
        self.children = {}
        self.terminal = False

    def insert(self, word):

                node.children[char] = Trie()
            node = node.children[char]
        node.terminal = True

        node = self
        for char in text:
            node = node.children.get(char)
            if node is None:
                return None
        return node

        node = self._walk(word)
        return node is not None and node.terminal

        return self._walk(prefix) is not None

            raise ValueError('negative size')
        self.parent = list(range(n))

        self._check(x)

            root = self.parent[root]

            old_parent = self.parent[x]
            self.parent[x] = root
            x = old_parent

            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

Iterative segment tree: point assignment and range sum

Answer repeated half-open range sums while individual array positions change.

Leaves hold individual values; a query takes whole sibling blocks whenever they fit.

Round leaf capacity up to a power of two and fill unused leaves with identity 0. Every node now summarizes one contiguous interval; each parent is the sum of its two children. During query, the accumulated sum plus the still-pending intervals equals the requested sum.

The reusable pattern

Pattern template · adapt names and helpers to the problem
# Leaves hold values; parents combine adjacent intervals.
tree[parent] = tree[2 * parent] + tree[2 * parent + 1]

# Point assignment: replace leaf, then repair its ancestors.
tree[position] = new_value
while position > 1:
    position //= 2
    tree[position] = tree[2 * position] + tree[2 * position + 1]

How to use it

  1. Choose power-of-two capacity size, place values at offset size, and build parent sums; unused leaves stay 0.
  2. For point set, replace one leaf and recompute ancestors; this is assignment, not increment.
  3. For [left,right), consume an odd left boundary and an odd right boundary before moving both boundaries to their parents.

set(2,10): t6=10, t3=14, t1=17.
query(1,4) -> 15; query(2,2) -> 0.

A point update changes only intervals containing that point, which lie on one root path. A range query takes complete blocks wherever possible instead of visiting every value; at each level only the two boundary blocks may need refinement.

Watch for: right is excluded, and set replaces the previous value. Segment trees require an associative combine operation and its identity, not an inverse: sum uses 0, min uses +infinity. This single-accumulator implementation exploits commutative addition; noncommutative operations need separate ordered left/right accumulators.

Complexity: For n nonempty input values, n <= size < 2n, so power-of-two padding still gives O(n) build time and storage. Point set and range query take O(log n) time for n >= 2, O(1) for n <= 1, and O(1) auxiliary space. An empty tree uses O(1) storage and accepts only query(0,0); no point index is valid.

class SegmentTree:
    def __init__(self, values):
        self.n = len(values)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.t = [0] * (2 * self.size)
        self.t[self.size:self.size + self.n] = values
        for p in range(self.size - 1, 0, -1):
            self.t[p] = self.t[2 * p] + self.t[2 * p + 1]

    def set(self, index, value):
        if not 0 <= index < self.n:
            raise IndexError('index out of bounds')
        p = self.size + index
        self.t[p] = value
        while p > 1:
            p //= 2
            self.t[p] = self.t[2 * p] + self.t[2 * p + 1]

    def query(self, left, right):
        if not 0 <= left <= right <= self.n:
            raise IndexError('invalid half-open range')
        left, right = left + self.size, right + self.size
        total = 0
        while left < right:
            if left % 2:
                total += self.t[left]
                left += 1
            if right % 2:
                right -= 1
                total += self.t[right]
            left //= 2
            right //= 2
        return total

01. Strategy Swap fee logic without touching checkout
Behavioral

Maya opens Neighborhood Kitchen and starts taking both pickup and delivery orders from her tiny storefront. Every order needs a different fee added on top of the subtotal, and she wants to add catering later without rewriting her checkout code.

What hurts now

Her checkout function has a growing if/elif chain checking order type just to decide how to add fees.

The small design move

Strategy pulls each fee calculation out into its own interchangeable function that takes a subtotal and returns a fee. The checkout code stays fixed and simply calls whichever policy function is plugged in for that order.

Dish→FeePolicy→Order

Remember: Swap fee logic without touching checkout

from dataclasses import dataclass

@dataclass(frozen=True)
class Dish:
    name: str
    price_cents: int

def pickup_fee(subtotal_cents):
    return 0

def delivery_fee(subtotal_cents):
    return 350

def catering_fee(subtotal_cents):
    return max(500, subtotal_cents // 10)

def total_cents(dishes, fee_policy):
    subtotal = sum(d.price_cents for d in dishes)
    return subtotal + fee_policy(subtotal)

order = [Dish("Soup", 700), Dish("Salad", 550)]

assert catering_total == 1750

Read the example

Each fee policy is a small pure function with the same signature, so total_cents() never needs to know which one it's calling. Adding a new fee type later means writing one more function, not editing existing logic.

What it costs / when to skip it

For only two or three fee types a single if/elif would be simpler and just as readable; Strategy pays off once policies multiply or need independent testing.

Do not confuse it with...

Unlike Template Method, Strategy swaps the whole fee algorithm via composition (a passed-in function), not by subclassing and overriding one step.

02. Decorator Stack add-ons around a plain dish
Structural

Regulars start asking Maya to customize their Soup with extra cheese or a gluten-free bun, sometimes both at once. She wants each add-on priced and named consistently without creating a new Dish subclass for every combination.

What hurts now

A single Dish class would need one field per possible add-on, and the name string would have to be rebuilt by hand for every combination.

The small design move

Decorator wraps a Dish in another object that implements the same name()/price_cents() interface, forwarding to the wrapped dish and adding its own bit on top. Stacking decorators lets any combination of add-ons compose naturally, in any order.

03. Composite Treat single dishes and bundles alike
Structural

Customers start asking for combo meals, and some combos should be nestable inside bigger family packs for office orders. Maya needs one price and description calculation that works whether she's looking at a single dish or a whole nested bundle.

What hurts now

Pricing code has separate branches for 'is this a single dish or a bundle', and nested bundles-of-bundles are not handled at all.

The small design move

Composite gives Dish and Bundle a shared interface with price_cents() and describe(), where a Bundle just delegates to whatever children it holds. Because a Bundle's children can themselves be Bundles, the same recursive call handles any depth of nesting for free.

Dish→Bundle→MenuComponent

class MenuComponent:
    def price_cents(self) -> int:
        raise NotImplementedError
    def describe(self) -> str:
        raise NotImplementedError

class Dish(MenuComponent):
    def __init__(self, name: str, price_cents: int):
        self.name = name
        self._price_cents = price_cents
    def price_cents(self) -> int:
        return self._price_cents
    def describe(self) -> str:
        return self.name

class Bundle(MenuComponent):
    def __init__(self, name: str):
        self.name = name
        self.children = []
    def add(self, component: MenuComponent) -> "Bundle":
        self.children.append(component)
        return self
    def price_cents(self) -> int:
        return sum(c.price_cents() for c in self.children)
    def describe(self) -> str:
        parts = ", ".join(c.describe() for c in self.children)
        return f"{self.name} [{parts}]"

soup = Dish("Soup", 700)
salad = Dish("Salad", 550)
bread = Dish("Bread", 200)

assert lunch_combo.price_cents() == 900
assert family_pack.price_cents() == 1450
assert family_pack.describe() == "Family Pack [Lunch Combo [Soup, Bread], Salad]"

Family Pack [Lunch Combo [Soup, Bread], Salad] = 1450 cents

Unlike Decorator's single wrapped child used to add behavior, Composite holds a collection of children used to represent a part-whole tree.

04. Iterator Walk order lines without exposing storage
Behavioral

Orders now routinely have many lines, and Maya's kitchen display and receipt printer both need to step through them one dish at a time, in the exact order they were added. She doesn't want either piece of code to know how Order stores its lines internally.

What hurts now

Both the kitchen display and the receipt printer reach directly into Order's private list and index it by hand, so any change to how lines are stored breaks two places at once.

The small design move

Iterator gives Order its own __iter__ that hands back a dedicated OrderIterator object tracking position independently of the Order itself. Client code just calls next() or loops with for, and the iterator raises StopIteration once every line has been visited exactly once.

Order→Dish→OrderIterator

Remember: Walk order lines without exposing storage

from dataclasses import dataclass

@dataclass(frozen=True)
class Dish:
    name: str
    price_cents: int

class Order:
    def __init__(self):
        self._lines = []
    def add(self, dish: Dish) -> None:
        self._lines.append(dish)
    def __iter__(self) -> "OrderIterator":
        return OrderIterator(tuple(self._lines))

class OrderIterator:
    def __init__(self, lines: tuple):
        self._lines = lines
        self._index = 0
    def __iter__(self) -> "OrderIterator":
        return self
    def __next__(self) -> Dish:
        if self._index >= len(self._lines):
            raise StopIteration
        line = self._lines[self._index]
        self._index += 1
        return line

order = Order()
for dish in (Dish("Soup", 700), Dish("Salad", 550), Dish("Bread", 200)):
    order.add(dish)
names = [line.name for line in order]

The tuple snapshot copies line references and the iterator adds a class; returning iter(tuple(self._lines)) would provide the same behavior here with less code.

05. Builder Assemble step by step, finalize once
Creational

Phone orders come in piecemeal while Maya juggles the register, a dish here, a delivery fee there, and she only wants a finished, immutable Order once everything is confirmed. She needs to prevent an accidentally incomplete order from ever reaching the kitchen.

What hurts now

Passing a giant Order constructor call with every field at once is error-prone over the phone, and there is no way to stop an empty order from being finalized.

The small design move

Builder collects dishes and fees step by step on a mutable OrderBuilder, returning itself from each call so steps can chain fluently. Only build() produces the final immutable BuiltOrder, and it can enforce invariants like refusing to build an order with zero dishes.

06. Prototype Clone a proven template, then customize
Creational

With step-by-step ordering working, office catering clients keep asking Maya for 'the usual' with small tweaks, and a wedding client requests upgraded soup plus a cake. She wants to start from her proven Office Lunch template each time without accidentally editing the original template.

What hurts now

Prototype clones a fully configured CateringTemplate using deepcopy so the copy owns entirely independent nested Dish objects, not shared references. Maya then mutates the clone's label and dish list freely, knowing the original template's dishes and prices are untouched.

07. Command Wrap each edit as an undoable object
Behavioral

After cloning a standard catering setup, staff adjust its draft at the order terminal, and sometimes the wrong dish gets added. Maya wants an in-memory edit history so staff can undo the most recent step without retyping the draft.

What hurts now

Staff currently just mutate the draft's line list directly, so there is no record of what changed and no way to undo the last action specifically.

The small design move

Command wraps each action, like adding a dish, as its own object holding the receiver (the Draft) and the details needed to both execute() and undo() that specific change. A CommandInvoker runs commands and keeps a history stack, so undoing just means popping the last command and calling its undo().

08. Memento Snapshot and restore, but never submitted
Behavioral

Before submitting a catering draft, staff want to freely experiment with the line items and be able to snap back to an earlier full version if a round of edits does not work out. Once a draft is actually submitted to the kitchen, though, Maya insists it must never be silently rewound.

What hurts now

Storing and restoring 'the whole draft as it was' by hand means either exposing Draft's internals to the caretaker or risking accidental edits to a saved snapshot.

The small design move

Memento has the Draft itself produce an immutable DraftMemento snapshot and later restore from one, so the Caretaker only stores and hands back opaque snapshots without reading their contents. The Draft checks snapshot ownership and rejects edits, saves, and restores after submission, keeping draft experimentation separate from submitted work.

Draft→DraftMemento→Caretaker

Remember: Snapshot and restore, but never submitted

Python 3.10+ · standalone checkpoint
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True, slots=True, repr=False)
class DraftMemento:
    _owner: object
    _lines: tuple[tuple[str, int], ...]

class Draft:
    def __init__(self):
        self._owner, self._lines, self._submitted = object(), [], False
    @property
    def lines(self) -> tuple:
        return tuple(self._lines)
    @property
    def submitted(self) -> bool:
        return self._submitted
    def _require_draft(self) -> None:
        if self._submitted:
            raise ValueError("only unsubmitted drafts may be edited or snapshotted")
    def add_line(self, name: str, price_cents: int) -> None:
        self._require_draft()
        self._lines.append((name, price_cents))
    def save(self) -> DraftMemento:
        self._require_draft()
        return DraftMemento(self._owner, tuple(self._lines))
    def restore(self, snapshot: DraftMemento) -> None:
        self._require_draft()
        if not isinstance(snapshot, DraftMemento) or snapshot._owner is not self._owner:
            raise ValueError("snapshot belongs to a different draft")
        self._lines = list(snapshot._lines)
    def submit(self) -> None:
        self._submitted = True

class Caretaker:
    def __init__(self):
        self.history = []
    def checkpoint(self, draft: Draft) -> None:
        self.history.append(draft.save())
    def undo(self, draft: Draft) -> None:
        if not self.history:
            raise ValueError("no checkpoint")
        draft.restore(self.history[-1])
        self.history.pop()

def rejected(action, error=ValueError):
    try:
        action()
    except error:
        return True
    raise RuntimeError("expected rejection")

draft.add_line("Soup", 700)
caretaker.checkpoint(draft)
snapshot = caretaker.history[-1]

caretaker.checkpoint(draft)
draft.submit()

09. State Let each stage own its own rules
Behavioral

Once a draft is submitted, it needs to move through real kitchen stages, placed, preparing, ready, and Maya wants it to be impossible to, say, cancel an order that is already preparing. Different stages should each know their own valid next steps rather than that logic living in one giant switch statement.

What hurts now

A plain status string plus if/elif checks scattered through the codebase makes it easy to accidentally allow an illegal transition, like cancelling a ready order.

The small design move

State represents each stage as its own object implementing advance() and cancel(), and the Order simply delegates to whatever state object it currently holds. Transitioning to a new stage means the state object itself swaps in the next state object, so illegal transitions like cancelling from PreparingState are rejected by the state object that is actually active.

10. Template Method Fix the sequence, vary each step
Behavioral

In the kitchen, every dish still follows the same overall sequence, gather ingredients, cook, maybe garnish, then plate, but the actual techniques differ wildly between a soup and a salad. Maya wants new cooks to only have to fill in the dish-specific steps, not re-learn the whole workflow.

Each dish's prep function currently duplicates the full gather-cook-garnish-plate sequence with only a couple of lines actually differing between recipes.

Behavioral

class Order:
    def __init__(self, order_id):
        self.order_id = order_id
        self.state = "draft"
        self.listeners = []

    def subscribe(self, callback):
        if callback not in self.listeners:
            self.listeners.append(callback)

    def unsubscribe(self, callback):
        if callback in self.listeners:
            self.listeners.remove(callback)

    def set_state(self, state):
        self.state = state
        failures = []
        for callback in tuple(self.listeners):
            try:
                callback(self.order_id, state)
            except Exception as error:
                failures.append(str(error))
        return failures

16. Mediator One coordinator owns the handoffs
Behavioral

Maya combines the earlier kitchen and packing workflows with the new courier handoff. The three workers must collaborate in order rather than merely observe status announcements.

What hurts now

The small design move

Give each worker a delivery coordinator instead of references to the other workers. Make that mediator own the handoff stages, start the next worker, and reject out-of-order completion events.

    def __init__(self, coordinator):

    def __init__(self, coordinator):
        self.coordinator = coordinator

        self.coordinator.log.append("courier collected")

    def __init__(self):
        self.stage, self.log = "queued", []
        self.kitchen = Kitchen(self)
        self.packer = Packer(self)
        self.courier = Courier(self)

        if self.stage != expected:
            raise ValueError("out-of-order handoff")

    def start(self):
        self.advance("queued", "cooking")
        self.kitchen.cook()
    def cooked(self):
        self.advance("cooking", "packing")
        self.packer.pack()
    def packed(self):
        self.advance("packing", "collecting")
        self.courier.collect()
    def collected(self):
        self.advance("collecting", "dispatched")

class Stock:
    def __init__(self, portions):
        self.portions = portions

        if quantity < 1 or quantity > self.portions:

    def quote(self, subtotal_cents):
        return 0 if subtotal_cents >= 5000 else 400

    def __init__(self):

18. Proxy Same door with a timed cache
Structural

Maya's delivery and catering status page now reuses the order states introduced earlier. Repeated refreshes ask for the same status even when kitchen progress has not changed.

What hurts now

Every refresh reads the underlying status source, while an unlimited cache would conceal a completed courier handoff.

The small design move

Put a caching stand-in in front of the status source with the same get_status interface. Bound staleness with a time-to-live and provide explicit invalidation after known changes, using an injected clock for deterministic checks.

Status caller→Caching proxy→Status source

Remember: Same door with a timed cache

Python 3.10+ · standalone checkpoint
class StatusSource:
    def __init__(self):
        self.states = {"NK-42": "cooking"}
        self.reads = 0
    def get_status(self, order_id):
        self.reads += 1
        return self.states[order_id]

class CachedStatus:
    def __init__(self, source, clock, ttl):
        if ttl <= 0:
            raise ValueError("ttl must be positive")
        self.source, self.clock, self.ttl = source, clock, ttl
        self.cache = {}
    def get_status(self, order_id):
        now = self.clock()
        cached = self.cache.get(order_id)
        if cached is not None and now < cached[0]:
            return cached[1]
        status = self.source.get_status(order_id)
        self.cache[order_id] = (now + self.ttl, status)
        return status
    def invalidate(self, order_id):
        self.cache.pop(order_id, None)

now = [0]

status = CachedStatus(source, clock=lambda: now[0], ttl=10)

assert initial == "cooking"
source.states["NK-42"] = "packed"
now[0] = 9
cached = status.get_status("NK-42")
assert cached == "cooking" and source.reads == 1
now[0] = 10
refreshed = status.get_status("NK-42")
assert refreshed == "packed" and source.reads == 2
source.states["NK-42"] = "dispatched"
status.invalidate("NK-42")
latest = status.get_status("NK-42")
assert latest == "dispatched" and source.reads == 3
print(f"Status: {latest}")
print(f"Backend reads: {source.reads}", end="")

Backend reads: 3

Both objects offer get_status(order_id), so callers can use either without changing their status lookup. now < cached[0] expires the entry exactly at the TTL boundary, while invalidate forces a fresh read immediately after a known update.

What it costs / when to skip it

Caching permits bounded stale answers and consumes memory, with eviction needed for a growing order list; direct reads are simpler when the source is cheap, and a real elapsed-time clock should be monotonic.

Do not confuse it with...

19. Chain of Responsibility First capable person handles it
Behavioral

What hurts now

The small design move

Link handlers from the counter through the shift lead to Maya, letting each accept a request or pass it onward. Stop at the first capable handler and return an explicit unhandled result when the chain ends.

@dataclass(frozen=True)

class Approver:
    def __init__(self, name, limit_cents, successor=None):

        self.successor = successor
        self.handled = []

            self.handled.append(request)
            return f"{request.cents}: approved by {self.name}"
        if self.successor is not None:
            return self.successor.handle(request)
        return f"{request.cents}: unhandled; manual review"

20. Interpreter Small rules become expression trees
Behavioral

Maya offers catering delivery perks based on the earlier order subtotals and delivery zones. She wants a small rule language whose meaning remains visible when conditions are combined.

What hurts now

Repeated nested conditions obscure which subtotal and zone combinations qualify for a catering perk.

The small design move

Represent a tiny grammar as expression objects, with terminal predicates reading order facts and nonterminals combining expressions. Evaluate a hand-built abstract syntax tree without a parser or Python eval.

Order facts→Rule expression tree→Eligibility result

Remember: Small rules become expression trees

Python 3.10+ · standalone checkpoint
from dataclasses import dataclass

# Grammar: rule := subtotal >= CENTS | zone = NAME
#                | (rule AND rule) | (rule OR rule)
# Hand-built AST only: there is no text parser.
@dataclass(frozen=True)
class Facts:
    subtotal_cents: int
    zone: str

# Terminal predicates have no child expressions.
@dataclass(frozen=True)
class SubtotalAtLeast:
    cents: int
    def evaluate(self, facts):
        return facts.subtotal_cents >= self.cents

@dataclass(frozen=True)
class ZoneIs:
    name: str
    def evaluate(self, facts):
        return facts.zone == self.name

# Nonterminals recursively interpret their children.
@dataclass(frozen=True)
class And:
    left: object
    right: object
    def evaluate(self, facts):
        return self.left.evaluate(facts) and self.right.evaluate(facts)

@dataclass(frozen=True)
class Or:
    left: object
    right: object
    def evaluate(self, facts):
        return self.left.evaluate(facts) or self.right.evaluate(facts)

rule = Or(And(SubtotalAtLeast(5000), ZoneIs("near")),
          SubtotalAtLeast(10000))
orders = [Facts(6000, "near"), Facts(6000, "far"), Facts(10000, "far")]
results = [rule.evaluate(order) for order in orders]
assert results == [True, False, True]
assert not rule.evaluate(Facts(4999, "near"))
print(f"Eligible: {results}", end="")
Expected output
Eligible: [True, False, True]

Read the example

SubtotalAtLeast and ZoneIs give meaning to the grammar's terminal predicates using the supplied facts. And and Or recursively evaluate child expressions with short-circuit semantics, so the object tree directly represents the composed rule.

What it costs / when to skip it

Each grammar feature adds expression types and tests, and accepting text would also require a parser and validation; a normal predicate function is simpler for one fixed rule.

Do not confuse it with...

Composite supplies a tree shape; Interpreter gives that tree a language grammar and evaluation meaning.

21. Visitor Stable menu welcomes new operations
Behavioral

Maya keeps the Dish and Bundle shapes established in the cafe's earlier menu work. Catering now needs both integer-cent totals and packing lists over those same stable node types.

What hurts now

Every new report adds another operation to both Dish and Bundle even though their menu structure has not changed.

The small design move

Give each node an accept method that dispatches to its type-specific visitor method. Put total calculation and packing-list generation in separate visitors, with each visitor owning traversal and accept never recursing.

Dish / Bundle nodes→accept dispatch→Total / packing visitors

Remember: Stable menu welcomes new operations

Python 3.10+ · standalone checkpoint
from dataclasses import dataclass

@dataclass(frozen=True)
class Dish:
    name: str
    unit_cents: int
    quantity: int
    def accept(self, visitor):
        return visitor.visit_dish(self)

@dataclass(frozen=True)
class Bundle:
    name: str
    children: tuple
    def accept(self, visitor):
        return visitor.visit_bundle(self)

class Total:
    def visit_dish(self, dish):
        return dish.unit_cents * dish.quantity
    def visit_bundle(self, bundle):
        return sum(child.accept(self) for child in bundle.children)

class PackingList:
    def visit_dish(self, dish):
        return [f"{dish.name} x{dish.quantity}"]
    def visit_bundle(self, bundle):
        return [entry for child in bundle.children
                for entry in child.accept(self)]

lunch = Bundle("Lunch", (
    Dish("Soup", 650, 2),
    Bundle("Side", (Dish("Bread", 250, 1),)),
))
total = lunch.accept(Total())
packing = lunch.accept(PackingList())
assert total == 1550
assert packing == ["Soup x2", "Bread x1"]
print(f"Total cents: {total}")
print("Packing: " + ", ".join(packing), end="")
Expected output
Total cents: 1550
Packing: Soup x2, Bread x1

Read the example

Dish.accept selects visit_dish and Bundle.accept selects visit_bundle, exposing the concrete node type to each operation. Only visitor methods traverse children, so each operation visits every tree occurrence once instead of double-counting through both accept and visitor recursion.

What it costs / when to skip it

Adding an operation is easy, but adding another node type such as Extra requires updating every visitor; ordinary functions or node methods are simpler when the menu types change frequently.

Do not confuse it with...

Composite organizes Dish and Bundle into a tree; Visitor separates operations from that structure using type-specific accept dispatch.

    version: int
    ingredients: tuple[tuple[str, int], ...]

Creational

from types import SimpleNamespace

# One-process, non-thread-safe demonstration only.
class KitchenSettings:
    _instance = None
    def __new__(cls, fee_bps=500):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
    def __init__(self, fee_bps=500):
        if getattr(self, "_initialized", False):
            return  # First initialization wins; later arguments are ignored.
        self.fee_bps = fee_bps
        self._initialized = True

def settings():
    return KitchenSettings()

def fee_cents(subtotal_cents, config=None):
    if config is None:
        config = settings()
    return subtotal_cents * config.fee_bps // 10000

# Isolate this test's class-level state, then restore the previous instance.
saved = KitchenSettings._instance
try:
    KitchenSettings._instance = None
    first = KitchenSettings(500)
    second = KitchenSettings(900)
    assert first is second is settings()
    assert second.fee_bps == 500
    assert fee_cents(2000) == 100
    assert fee_cents(2000, SimpleNamespace(fee_bps=0)) == 0
    print(f"Same instance: {first is second}")
    print(f"Default fee cents: {fee_cents(2000)}")
    print(f"Injected fee cents: {fee_cents(2000, SimpleNamespace(fee_bps=0))}", end="")
finally:
    KitchenSettings._instance = saved
Expected output
Same instance: True
Default fee cents: 100
Injected fee cents: 0

Read the example

The test restores class-level state in finally, and an explicitly injected configuration avoids the global dependency for fee tests.

What it costs / when to skip it

Global access hides dependencies, complicates state isolation, and needs additional design for threads or multiple processes; creating one ordinary settings object at startup and injecting it is usually simpler and safer.

Do not confuse it with...

RAM indexingJump straight to the slot

Rule: In this toy address model, slot i starts at base + i * width for 0 <= i < size. CPython lists hold a contiguous array of reference slots pointing to objects, not Python integers stored inline. The base and width below are invented, not measured addresses or hardware guarantees.

Static arraysMake a hole; keep the order

Rule: 0 <= size <= capacity. Live values occupy slots [0, size); the suffix is unused. A Python list simulates the fixed backing store: this class never changes its length.

Python 3.10+ · complete runnable example
class FixedArray:
    def __init__(self, capacity):
        if capacity < 0:
            raise ValueError('negative capacity')
        self.slots = [None] * capacity
        self.size = 0

    def insert(self, i, value):
        if not 0 <= i <= self.size:
            raise IndexError(i)
        if self.size == len(self.slots):
            raise OverflowError('full')
        for j in range(self.size, i, -1):
            self.slots[j] = self.slots[j - 1]
        self.slots[i] = value
        self.size += 1

    def delete(self, i):
        if not 0 <= i < self.size:
            raise IndexError(i)
        value = self.slots[i]
        for j in range(i, self.size - 1):
            self.slots[j] = self.slots[j + 1]
        self.size -= 1
        self.slots[self.size] = None
        return value

buffer = FixedArray(5)
for value in [10, 20, 30]:
    buffer.insert(buffer.size, value)
buffer.insert(1, 15)
assert buffer.slots == [10, 15, 20, 30, None]
print('insert:', buffer.slots, 'size:', buffer.size)
removed = buffer.delete(2)
assert removed == 20 and buffer.size == 3
print('delete:', buffer.slots, 'capacity:', len(buffer.slots))
empty = FixedArray(0)
try:
    empty.insert(0, 7)
except OverflowError:
    print('full: OverflowError')
else:
    raise AssertionError('full buffer accepted insertion')

Why it works and edge cases
  1. Check the logical index and available capacity.
  2. Insert by shifting right from the end; delete by shifting left from the hole.
  3. Update size and clear the newly unused slot after deletion.

Watch for: Shift right from the end or you overwrite values not yet copied. None is only a cleared-slot marker: size, not value equality with None, decides which slots are live.

Complexity details: Let n be the size before an operation, C the fixed capacity, and i a valid logical index. Initialization takes O(C) time and O(C) reference storage. Direct slot access is O(1). Insertion shifts n-i references; deletion shifts n-i-1, so either takes O(n-i) time away from the end and O(1) at the end, with O(1) auxiliary space. Excludes printing and stored objects. Index arithmetic is assumed unit-cost on machine-sized integers; arbitrary-size Python arithmetic is not generally constant-time.

Dynamic arraysFull? Grow, copy, then append

Rule: Live references occupy [0, size), with size <= capacity. This teaching implementation starts at capacity 1 and doubles only when full; it makes no claim about CPython's growth factors or hidden list capacity.

Python 3.10+ · complete runnable example
class GrowingArray:
    def __init__(self):
        self.slots = [None]
        self.size = 0

    def append(self, value):
        if self.size == len(self.slots):
            larger = [None] * (2 * len(self.slots))
            for i in range(self.size):
                larger[i] = self.slots[i]
            self.slots = larger
        self.slots[self.size] = value
        self.size += 1

    def __getitem__(self, i):
        if not 0 <= i < self.size:
            raise IndexError(i)
        return self.slots[i]

Deeper framework explanation

Maintain 0 <= size <= capacity, with live references in [0, size) and unused storage in [size, capacity). In the fixed-width RAM model, slot i is at base + i * width; this locates a reference slot, not necessarily the referenced object. Access and replacement at a valid index take O(1) under machine-word assumptions, but finding a value in an unsorted array still takes O(n). None can be a live value: the size boundary, not a sentinel value, determines membership.

Preserve the occupied prefix when changing its length. To insert at i, copy the suffix rightward from its end so no unread reference is overwritten; deletion copies leftward from the hole and clears the abandoned last slot. A fixed buffer rejects insertion when full, whereas a dynamic buffer allocates a larger store and copies live references before appending. Geometric growth makes total copying over m appends O(m), hence O(1) amortized append, although a single growth costs O(n); arbitrary-position insertion still shifts O(n-i) references. Doubling below is a teaching policy, not CPython's exact allocation rule.

TEMPLATE: insert into a fixed occupied prefix
def insert_slot(slots, size, i, value):
    # slots is a simulated fixed-capacity backing store.
    if not 0 <= size <= len(slots):
        raise ValueError('invalid size')
    if not 0 <= i <= size:
        raise IndexError(i)
    if size == len(slots):
        raise OverflowError('full')
    for j in range(size, i, -1):
        slots[j] = slots[j - 1]
    slots[i] = value
    return size + 1

The caller must retain the returned logical size; insertion permits i == size, but ordinary element access requires i < size.

TEMPLATE: grow before appending
def append_slot(slots, size, value):
    # Doubling models growth, not CPython's exact policy.
    if not 0 <= size <= len(slots):
        raise ValueError('invalid size')
    if size == len(slots):
        larger = [None] * max(1, 2 * len(slots))
        for i in range(size):
            larger[i] = slots[i]
        slots = larger
    slots[size] = value
    return slots, size + 1

Live elements must occupy [0, size), and the caller must retain both returned values because growth replaces the backing store.

Rule: fib(k) computes F(k) once per cache lifetime, with F(0)=0 and F(1)=1. Before rolling-loop step k, (a,b)=(F(k),F(k+1)). Inputs are nonnegative integers.

from functools import cache

@cache
def fib(n):
    if n < 0:
        raise ValueError('n must be nonnegative')
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

def fib_rolling(n):
    if n < 0:
        raise ValueError('n must be nonnegative')
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

Watch for: Creating a fresh cache inside every recursive call defeats reuse. An unbounded cache retains answers across calls; cache only pure computations and clear it when its lifetime should end.

Complexity details: Let n be the requested index, starting with an empty cache. Naive uncached recursion makes Theta(phi^n) calls, phi=(1+sqrt(5))/2, and uses O(n) stack frames. Memoization uses O(n+1) expected time, O(n+1) cache entries, and O(n+1) stack frames; rolling uses O(n+1) time and O(1) integer variables. These assume unit-cost arithmetic and expected O(1) cache operations, excluding returned/printed output. Python F(n) has Theta(n) bits: rolling state needs O(n) bits, cached Fibonacci values O(n^2) bits, and additions are not O(1). Memoization still hits Python's recursion-depth limit on sufficiently deep cold calls; rolling avoids that limit.

Practice: Name a subproblem by its minimal state and memoize it: stair counts, grid paths, and edit-distance states use the same pattern.

Deeper framework explanation

Give solve(state) a precise return contract, then identify a nonnegative integer measure that strictly decreases on every recursive edge. Handle the minimum states directly with correct base answers. Assuming each smaller call fulfills the contract, show that the combining step fulfills it for the current state: this is the inductive correctness argument. Each suspended call keeps its own local state and unfinished work on the stack, so maximum active depth measures stack usage while the entire call tree measures total work.

Termination and repeated work are separate questions. A terminating Fibonacci recursion can still recompute the same state exponentially often; memoization stores completed answers so each distinct state is evaluated once per cache lifetime. Cache keys must contain every input that affects a pure result, and the cache must be shared by the recursive calls. Caching does not make a cyclic recurrence terminate, because an answer is not stored until its call returns, and it does not remove Python's recursion-depth limit. Use a loop or explicit stack for deep chains, and rolling state when only a few previous answers are needed.

Insertion sortGrow a sorted prefix

Rule: Before index i, a[:i] is sorted. Save a[i], shift strictly larger keys right, then fill the hole. Equal keys never cross, so the sort is stable.

Python 3.10+ · complete runnable example
def insertion_sort(a, key=lambda x: x):
    for i in range(1, len(a)):
        item = a[i]
        item_key = key(item)
        j = i - 1
        while j >= 0 and key(a[j]) > item_key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = item
    return a

Merge sortThe smaller exposed head wins

Rule: Each recursive result is sorted. During merge, out contains the smallest consumed items in stable order; left[i] and right[j] are the next candidates.

Python 3.10+ · complete runnable example
def merge_sort(a, key=lambda x: x):
    if len(a) <= 1:
        return a.copy()
    mid = len(a) // 2
    left = merge_sort(a[:mid], key)
    right = merge_sort(a[mid:], key)
    out = []
    i = j = 0
    while i < len(left) and j < len(right):
        if key(left[i]) <= key(right[j]):
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    out.extend(left[i:])
    out.extend(right[j:])
    return out

Quick sortSmall | equal | unknown | large

Rule: With inclusive lo and hi and a saved pivot: [lo,lt)<pivot, [lt,i)==pivot, [i,gt] unknown, (gt,hi]>pivot. When i>gt, recurse only outside [lt,gt].

Python 3.10+ · complete runnable example
def quick_sort(a):
    def sort(lo, hi):
        while lo < hi:
            pivot = a[(lo + hi) // 2]
            lt = i = lo
            gt = hi
            while i <= gt:
                if a[i] < pivot:
                    a[lt], a[i] = a[i], a[lt]
                    lt += 1
                    i += 1
                elif a[i] > pivot:
                    a[i], a[gt] = a[gt], a[i]
                    gt -= 1
                else:
                    i += 1
            # Recurse on the smaller outer block; loop over the larger.
            if lt - lo < hi - gt:
                sort(lo, lt - 1)
                lo = gt + 1
            else:
                sort(gt + 1, hi)
                hi = lt - 1
    sort(0, len(a) - 1)
    return a

  1. Save the middle value as pivot; set lt=i=lo and gt=hi.
  2. Move < left, > right, or advance past =; recheck items swapped from right.
  3. Sort only [lo,lt-1] and [gt+1,hi]; the equal block is done.
[3,2,2,1], pivot=2, (lt,i,gt)=(0,0,3): > swap -> [1,2,2,3], (0,0,2); < swap -> (1,1,2); two = steps -> (1,3,2). Final [1 | 2,2 | 3].

Complexity details: n items: each partition is Theta(block length); balanced splits Theta(n log n), worst Theta(n^2), all equal Theta(n). Middle-position pivot is not a median guarantee; randomized pivot gives expected O(n log n). Smaller-side recursion here limits auxiliary stack to O(log n) even with bad splits; partition itself O(1). Empty input O(1); comparisons/assignments assumed O(1).

Practice: Randomize pivot choice to reduce adversarial splits, without changing region rules. For quickselect, keep only the outer region containing the desired rank, or stop inside the equal block.

Bucket sortDistribute → sort locally → join

Rule: Every item in bucket b is <= every item in a later bucket. Buckets are not internally sorted until the insertion-sort pass.

def bucket_sort(values):
    if not values:
        return []
    if any(type(x) is not int for x in values):
        raise TypeError('bucket_sort requires integers')
    low, high = min(values), max(values)
    k = len(values)

    buckets = [[] for _ in range(k)]

            while j >= 0 and bucket[j] > x:
                bucket[j + 1] = bucket[j]
                j -= 1
            bucket[j + 1] = x
        out.extend(bucket)
    return out

Deeper framework explanation

Start with the ordering contract: ascending or descending keys, whether equal-key items must keep their original relative order, whether input may be mutated, and what extra memory is allowed. Then name the region already proved correct and the unknown region each step shrinks. In insertion sort the prefix is sorted; in merging the output contains the smallest items consumed from two sorted runs; in three-way partitioning the smaller, equal, unknown, and larger regions have explicit boundaries. Preserve the original multiset throughout, and prove both the ordering promise and progress rather than merely observing a few successful swaps.

The invariant determines the implementation and its limits. Insertion shifts larger items and is effective on small or nearly sorted data, but can take O(n^2). Merge sort combines sorted halves in linear work per level for O(n log n) time, using O(n) auxiliary storage in the array version. Quicksort finishes a pivot-equal region and sorts only the outside regions; unbalanced splits can still give O(n^2), while randomized pivots give expected O(n log n). Numeric buckets rely on ordered value ranges and still need internal sorting; expected linear behavior needs suitable distribution assumptions. The fragments below teach these distinct boundaries, not interchangeable complete sorts.

HeapifyChildren first; parents next

Rule: Before processing i from n//2-1 down to 0, both child subtrees of i are heaps. Sifting i down makes its whole subtree a heap without damaging finished descendants.

def heapify_bottom_up(a):
    n = len(a)
    for start in range(n // 2 - 1, -1, -1):
        i = start
        while 2 * i + 1 < n:
            child = 2 * i + 1
            if child + 1 < n and a[child + 1] < a[child]:
                child += 1
            if a[i] <= a[child]:

            a[i], a[child] = a[child], a[i]
            i = child
    return a

Rule: low represents the lower half as negated values in a min-heap; high is a normal min-heap. Every logical low value <= every high value: -low[0]<=high[0] when both exist. len(low)==len(high) or len(low)==len(high)+1.

import heapq


class MedianStream:
    def __init__(self):
        self.low = []
        self.high = []

    def add(self, x):
        if not self.low or x <= -self.low[0]:
            heapq.heappush(self.low, -x)
        else:
            heapq.heappush(self.high, x)
        if len(self.low) > len(self.high) + 1:
            heapq.heappush(self.high, -heapq.heappop(self.low))
        elif len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))
        assert len(self.low) in (len(self.high), len(self.high) + 1)
        assert not self.high or -self.low[0] <= self.high[0]

    def median(self):
        if not self.low:
            raise ValueError('median of empty stream')
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2

Deeper framework explanation

Maintain the min-heap promise that each parent is no greater than its children. In zero-based array storage, children of i are 2*i+1 and 2*i+2, and the parent of a nonroot is (i-1)//2. Following ancestors proves the root is a global minimum, but gives no order between siblings or separate subtrees. Push repairs an upward path and pop repairs a downward path, using O(log n) comparisons; peek is O(1), and bottom-up heapify builds an available batch in O(n). Python list resizing makes operation-time bounds amortized, and neither iteration nor an arbitrary index reveals sorted rank.

Choose what the root represents before choosing heap operations. A priority queue exposes the next task; a size-k min-heap for the largest k exposes the weakest retained candidate. A median structure instead partitions every value between a lower max-heap and an upper min-heap: every lower value must be <= every upper value, and the lower size must equal the upper size or exceed it by one. Both promises are necessary to identify the middle. Python 3.10 heapq is a min-heap API, so negate numeric lower-half values; use a unique sequence number between priority and payload to handle ties without comparing unrelated payload objects.

from collections import deque


def shortest_steps(grid, start, goal):
    rows = len(grid)
    cols = len(grid[0]) if rows else 0
    if any(len(row) != cols for row in grid):
        raise ValueError('grid must be rectangular')
    for r, c in (start, goal):
        if not (0 <= r < rows and 0 <= c < cols) or grid[r][c] != 0:
            return -1
    queue = deque([(start[0], start[1], 0)])
    seen = {start}
    while queue:
        r, c, distance = queue.popleft()
        if (r, c) == goal:
            return distance
        for dr, dc in ((0, 1), (1, 0), (0, -1), (-1, 0)):
            nr, nc = r + dr, c + dc
            if not (0 <= nr < rows and 0 <= nc < cols):
                continue
            if grid[nr][nc] == 0 and (nr, nc) not in seen:
                seen.add((nr, nc))
                queue.append((nr, nc, distance + 1))
    return -1

DijkstraCheapest whole journey first

Rule: dist[v] is the best discovered source-to-v cost. A popped entry is expanded only if it matches dist[v]; with nonnegative weights that current minimum distance is final.

Python 3.10+ · complete runnable example
from heapq import heappop, heappush
from math import inf


def dijkstra(adj, source):
    if not 0 <= source < len(adj):
        raise ValueError('invalid source')
    for neighbors in adj:
        for v, weight in neighbors:
            if not 0 <= v < len(adj):
                raise ValueError('invalid endpoint')
            if weight < 0:
                raise ValueError('negative weight')
    dist = [inf] * len(adj)
    dist[source] = 0
    heap = [(0, source)]
    while heap:
        distance, u = heappop(heap)
        if distance != dist[u]:
            continue
        for v, weight in adj[u]:
            candidate = distance + weight
            if candidate < dist[v]:
                dist[v] = candidate
                heappush(heap, (candidate, v))
    return dist


def main():
    adj = [[(1, 10), (2, 1)], [(3, 1)], [(1, 1), (3, 5)], [], []]
    distances = dijkstra(adj, 0)
    ties = dijkstra([[(1, 1), (2, 1)], [], []], 0)
    assert distances == [0, 2, 1, 3, inf]
    assert ties == [0, 1, 1]
    print('distances:', distances)
    try:
        dijkstra([[], [(1, -1)]], 0)
    except ValueError as error:
        print('rejected:', error)
    else:
        raise AssertionError('negative weight accepted')

PrimCheapest connection to the tree

Rule: Every accepted non-root heap entry joins a new vertex by a cheapest crossing edge. Entries leading to already visited vertices are discarded.

from heapq import heappop, heappush


def prim_forest(adj):
    visited = set()
    chosen = []
    total = 0
    components = 0
    for root in range(len(adj)):
        if root in visited:
            continue
        components += 1
        heap = [(0, root, -1)]
        while heap:
            weight, u, parent = heappop(heap)
            if u in visited:
                continue
            visited.add(u)
            if parent != -1:
                chosen.append((parent, u, weight))
                total += weight
            for v, edge_weight in adj[u]:
                if v not in visited:
                    heappush(heap, (edge_weight, v, u))
    return total, chosen, components

KruskalCheapest edge joining different groups

Rule: The accepted edges are acyclic, and the disjoint-set structure represents exactly their connected components. Each successful union decreases the component count by one.

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while x != self.parent[x]:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True


def kruskal_forest(vertex_count, edges):
    if vertex_count < 0:
        raise ValueError('vertex_count must be nonnegative')
    ordered = sorted(edges, key=lambda edge: (edge[2], edge[0], edge[1]))
    if any(not (0 <= u < vertex_count and 0 <= v < vertex_count)
           for u, v, weight in ordered):
        raise ValueError('invalid endpoint')
    dsu = DSU(vertex_count)
    chosen = []
    total = 0
    components = vertex_count
    for u, v, weight in ordered:
        if dsu.union(u, v):
            chosen.append((u, v, weight))
            total += weight
            components -= 1
    return total, chosen, components


def main():
    edges = [(0, 2, 3), (0, 1, 2), (1, 2, 2)]
    total, chosen, count = kruskal_forest(4, edges)
    negative = kruskal_forest(2, [(0, 1, -4), (0, 1, 2), (0, 0, -8)])
    empty = kruskal_forest(0, [])
    assert (total, chosen, count) == (4, [(0, 1, 2), (1, 2, 2)], 2)
    assert len(chosen) == 4 - count
    assert negative == (-4, [(0, 1, -4)], 1)
    assert empty == (0, [], 0)
    print('total:', total)
    print('edges:', chosen)
    print('components:', count)
    print('connected:', count == 1)

Topological sortNo prerequisites left? Release it

Rule: indegree[v] counts incoming edges from unprocessed vertices. The queue contains ready vertices, each enqueued once when its remaining indegree reaches zero.

Python 3.10+ · complete runnable example
from collections import deque


def topological_order(adj):
    indegree = [0] * len(adj)
    for neighbors in adj:
        for v in neighbors:
            indegree[v] += 1
    queue = deque(v for v, degree in enumerate(indegree) if degree == 0)
    result = []
    while queue:
        u = queue.popleft()
        result.append(u)
        for v in adj[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)
    if len(result) != len(adj):
        raise ValueError('directed cycle')
    return result


def main():
    adj = [[2], [2], [3], [], []]
    order = topological_order(adj)
    parallel = topological_order([[1, 1], []])
    empty = topological_order([])
    assert order == [0, 1, 4, 2, 3]
    assert parallel == [0, 1] and empty == []
    position = {v: i for i, v in enumerate(order)}
    assert all(position[u] < position[v]
               for u, neighbors in enumerate(adj) for v in neighbors)
    print('order:', order)
    try:
        topological_order([[1], [0], []])
    except ValueError as error:
        print('rejected:', error)
    else:
        raise AssertionError('cycle accepted')

Deeper framework explanation

First specify edge direction, weights, and the complete vertex set, including isolated vertices. Adjacency lists use O(V+E) storage; undirected edges need entries in both directions, and a grid can generate neighbors without storing explicit edges. For reachability, maintain a discovered set and mark when scheduling work to avoid repeated pending entries. A DFS stack follows branches, whereas a BFS FIFO queue expands nondecreasing edge counts: with unit-cost moves, first discovery fixes shortest steps because every shorter predecessor layer was processed earlier. A traversal from one source does not cover disconnected components; iterate unseen roots when that is the question.

Weighted and dependency problems require different promises, not merely different containers. Dijkstra keeps best discovered source-to-vertex costs and expands a nonstale minimum using distance[u] + weight; nonnegative weights make that distance final. Prim grows an undirected tree using the cheapest single edge crossing from included to excluded vertices; the cut property makes this safe even with negative weights, and restarting at unseen roots yields a forest. Kruskal instead sorts edges and joins distinct components. Kahn tracks incoming edges from unprocessed vertices and releases a vertex only when that count becomes zero: its queue represents satisfied prerequisites, not shortest-distance layers. If fewer than V vertices are released, a directed cycle prevents a full ordering.
