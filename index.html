Before using the template

The predicate must be fixed and monotonic.

  • 1
    Fixed

    valid(i) keeps the same meaning while l and r move.

  • 2
    Monotonic

    Its results have exactly one boundary: F...T or T...F.

The operator does not decide FIRST or LAST

The boolean shape decides it.

Exact target

The boundary gives a candidate. Verify: ans != -1 and nums[ans] == target.

Rotated sorted arrays

Find the pivot, select one sorted side, then run boundary search.

Distinct values

Freeze last = nums[-1]. The first nums[i] <= last is the pivot.

[4,5,6,7,0,1,2] -> F F F F T T T

FIRST valid -> pivot

Duplicate values

Leading copies of last create an unwanted True prefix.

T T F F T T T -> skip prefix -> F F T T T

Check target == last -> skip leading last values

Complexity with unrestricted duplicates

Usually O(log n), but worst case O(n). Equal values can hide the pivot, so the linear worst case is unavoidable.

Algorithm 02

Backtracking

Build one candidate step by step. Explore each valid choice, then undo it so the next branch starts clean.

How to think Framework Visualize Decisions Problem map Solutions

How to think inside dfs

Focus on one call, not the entire recursion tree.

dfs(state, path)

path is what you have built. state tells you where you are and which choices remain.

  • 1
    Stop

    If path is complete, save path.copy() and return.

  • 2
    Choose and explore

    Add one valid choice, update state, and recurse.

  • 3
    Undo

    Remove the choice so the next branch starts from the same path.

Concrete example

dfs(1, [1]) means: "I chose 1. Now decide whether to take or skip nums[1]."

One framework

Each problem changes the state, choices, completion rule, and pruning rule.

Universal backtracking template
res = []

def backtrack(state, path):
    if complete(state, path):
        res.append(path.copy())
        return

    for choice in choices(state, path):
        if not valid(choice, state, path):
            continue

        path.append(choice)                    # choose
        next_state = apply(choice, state)

        backtrack(next_state, path)             # explore

        undo(choice, state)                    # if state is mutable
        path.pop()                             # undo path

backtrack(initial_state, [])
return res

class Solution:
    def permute(self, nums: List[int]) -> List[List[int]]:
        res = []
        used = [False] * len(nums)

        def backtrack(path):
            if len(path) == len(nums):
                res.append(path.copy())
                return

            for i in range(len(nums)):
                if used[i]:
                    continue

                path.append(nums[i])
                used[i] = True
                backtrack(path)
                used[i] = False
                path.pop()

        backtrack([])
        return res

Open while open_count < n. Close only while close_count < open_count.

Python
class Solution:
    def generateParenthesis(self, n: int) -> List[str]:
        res = []

        def backtrack(open_count, close_count, path):
            if open_count == close_count == n:
                res.append("".join(path))
                return

            if open_count < n:
                path.append("(")
                backtrack(open_count + 1, close_count, path)
                path.pop()

            if close_count < open_count:
                path.append(")")
                backtrack(open_count, close_count + 1, path)
                path.pop()

        backtrack(0, 0, [])
        return res

class Solution:
    def trap(self, height: List[int]) -> int:
        if len(height) < 2:
            return 0

        leftMaxArr = [0 for _ in range(len(height))]
        rightMaxArr = [0 for _ in range(len(height))]

        leftMax = height[0]
        for i in range(1,len(height)):
            leftMaxArr[i] = leftMax
            leftMax = max(leftMax, height[i])

        rightMax = height[-1]
        for i in range(len(height)-2,-1,-1):
            rightMaxArr[i] = rightMax
            rightMax = max(rightMax,height[i])

        allowWater = 0
        for i in range(len(height)):
            minHeight = min(leftMaxArr[i],rightMaxArr[i])
            allowWater += (minHeight-height[i]) if minHeight-height[i] >0 else 0
        return allowWater

01. Strategy Swap fee logic without touching checkout
Behavioral

Maya opens Neighborhood Kitchen and starts taking both pickup and delivery orders from her tiny storefront. Every order needs a different fee added on top of the subtotal, and she wants to add catering later without rewriting her checkout code.

What hurts now

Her checkout function has a growing if/elif chain checking order type just to decide how to add fees.

The small design move

Strategy pulls each fee calculation out into its own interchangeable function that takes a subtotal and returns a fee. The checkout code stays fixed and simply calls whichever policy function is plugged in for that order.

Structural

Structural

04. Iterator Walk order lines without exposing storage
Behavioral

Orders now routinely have many lines, and Maya's kitchen display and receipt printer both need to step through them one dish at a time, in the exact order they were added. She doesn't want either piece of code to know how Order stores its lines internally.

What hurts now

Both the kitchen display and the receipt printer reach directly into Order's private list and index it by hand, so any change to how lines are stored breaks two places at once.

The small design move

Iterator gives Order its own __iter__ that hands back a dedicated OrderIterator object tracking position independently of the Order itself. Client code just calls next() or loops with for, and the iterator raises StopIteration once every line has been visited exactly once.

            raise StopIteration
        line = self._lines[self._index]
        self._index += 1
        return line

07. Command Wrap each edit as an undoable object
Behavioral

After cloning a standard catering setup, staff adjust its draft at the order terminal, and sometimes the wrong dish gets added. Maya wants an in-memory edit history so staff can undo the most recent step without retyping the draft.

What hurts now

Staff currently just mutate the draft's line list directly, so there is no record of what changed and no way to undo the last action specifically.

The small design move

Command wraps each action, like adding a dish, as its own object holding the receiver (the Draft) and the details needed to both execute() and undo() that specific change. A CommandInvoker runs commands and keeps a history stack, so undoing just means popping the last command and calling its undo().

Draft→Command→CommandInvoker

class Draft:
    def __init__(self):
        self.lines = []
    def add_line(self, name: str, price_cents: int) -> None:
        self.lines.append((name, price_cents))
    def remove_last(self) -> tuple:
        return self.lines.pop()

class Command:
    def execute(self) -> None:
        raise NotImplementedError
    def undo(self) -> None:
        raise NotImplementedError

class AddDishCommand(Command):
    def __init__(self, draft: Draft, name: str, price_cents: int):
        self._draft = draft
        self._name = name
        self._price_cents = price_cents
    def execute(self) -> None:
        self._draft.add_line(self._name, self._price_cents)
    def undo(self) -> None:
        self._draft.remove_last()

    def __init__(self):

    def run(self, command: Command) -> None:

        self._history.append(command)
    def undo_last(self) -> None:
        if not self._history:
            raise ValueError("no commands to undo")
        command = self._history.pop()
        command.undo()

08. Memento Snapshot and restore, but never submitted
Behavioral

Before submitting a catering draft, staff want to freely experiment with the line items and be able to snap back to an earlier full version if a round of edits does not work out. Once a draft is actually submitted to the kitchen, though, Maya insists it must never be silently rewound.

What hurts now

Storing and restoring 'the whole draft as it was' by hand means either exposing Draft's internals to the caretaker or risking accidental edits to a saved snapshot.

The small design move

Memento has the Draft itself produce an immutable DraftMemento snapshot and later restore from one, so the Caretaker only stores and hands back opaque snapshots without reading their contents. The Draft checks snapshot ownership and rejects edits, saves, and restores after submission, keeping draft experimentation separate from submitted work.

Draft→DraftMemento→Caretaker

Remember: Snapshot and restore, but never submitted

Python 3.10+ · standalone checkpoint
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True, slots=True, repr=False)
class DraftMemento:
    _owner: object
    _lines: tuple[tuple[str, int], ...]

class Draft:
    def __init__(self):
        self._owner, self._lines, self._submitted = object(), [], False
    @property
    def lines(self) -> tuple:
        return tuple(self._lines)
    @property
    def submitted(self) -> bool:
        return self._submitted
    def _require_draft(self) -> None:
        if self._submitted:
            raise ValueError("only unsubmitted drafts may be edited or snapshotted")
    def add_line(self, name: str, price_cents: int) -> None:
        self._require_draft()
        self._lines.append((name, price_cents))
    def save(self) -> DraftMemento:
        self._require_draft()
        return DraftMemento(self._owner, tuple(self._lines))
    def restore(self, snapshot: DraftMemento) -> None:
        self._require_draft()
        if not isinstance(snapshot, DraftMemento) or snapshot._owner is not self._owner:
            raise ValueError("snapshot belongs to a different draft")
        self._lines = list(snapshot._lines)
    def submit(self) -> None:
        self._submitted = True

class Caretaker:
    def __init__(self):
        self.history = []
    def checkpoint(self, draft: Draft) -> None:
        self.history.append(draft.save())
    def undo(self, draft: Draft) -> None:
        if not self.history:
            raise ValueError("no checkpoint")
        draft.restore(self.history[-1])
        self.history.pop()

def rejected(action, error=ValueError):
    try:
        action()
    except error:
        return True
    raise RuntimeError("expected rejection")

draft, caretaker = Draft(), Caretaker()
draft.add_line("Soup", 700)
caretaker.checkpoint(draft)
snapshot = caretaker.history[-1]
foreign = rejected(lambda: Draft().restore(snapshot))
frozen = rejected(lambda: setattr(snapshot, "_lines", ()), FrozenInstanceError)
draft.add_line("Salad", 550)
caretaker.undo(draft)
assert draft.lines == (("Soup", 700),) and foreign and frozen
caretaker.checkpoint(draft)
draft.submit()
failed = rejected(lambda: caretaker.undo(draft))
blocked_save = rejected(draft.save)
blocked_edit = rejected(lambda: draft.add_line("Tea", 300))
assert failed and blocked_save and blocked_edit and len(caretaker.history) == 1
print(f"lines={list(draft.lines)} submitted={draft.submitted} restore_blocked={failed}")
Expected output
lines=[('Soup', 700)] submitted=True restore_blocked=True

Read the example

A frozen DraftMemento holds immutable line tuples and an identity token, while Caretaker treats it as an opaque handle and never reads its fields. Draft alone saves and restores state through its public API, rejecting foreign snapshots and any save, edit, or restore after submission. Underscore privacy is a Python convention rather than a security boundary, and rejected restores leave history intact.

What it costs / when to skip it

For a draft with only one or two fields, simply storing a manual copy of the list would be simpler than a dedicated memento class; the pattern earns its keep as the snapshot's shape grows or needs origin-binding checks.

Do not confuse it with...

Unlike Command's recorded action and inverse operation, Memento captures restorable state without exposing it to the caretaker; commands can also use mementos to implement undo.

09. State Let each stage own its own rules
Behavioral

Once a draft is submitted, it needs to move through real kitchen stages, placed, preparing, ready, and Maya wants it to be impossible to, say, cancel an order that is already preparing. Different stages should each know their own valid next steps rather than that logic living in one giant switch statement.

What hurts now

A plain status string plus if/elif checks scattered through the codebase makes it easy to accidentally allow an illegal transition, like cancelling a ready order.

The small design move

State represents each stage as its own object implementing advance() and cancel(), and the Order simply delegates to whatever state object it currently holds. Transitioning to a new stage means the state object itself swaps in the next state object, so illegal transitions like cancelling from PreparingState are rejected by the state object that is actually active.

Behavioral

class Order:
    def __init__(self, order_id):
        self.order_id = order_id
        self.state = "draft"
        self.listeners = []

    def subscribe(self, callback):
        if callback not in self.listeners:
            self.listeners.append(callback)

    def unsubscribe(self, callback):
        if callback in self.listeners:
            self.listeners.remove(callback)

    def set_state(self, state):
        self.state = state
        failures = []
        for callback in tuple(self.listeners):
            try:
                callback(self.order_id, state)
            except Exception as error:
                failures.append(str(error))
        return failures

    seen.append(f"{order_id}:{state}")

    raise RuntimeError("notice unavailable")

        self.courier.collect()
    def collected(self):

    def __init__(self, portions):

    def __init__(self):

class StatusSource:
    def __init__(self):
        self.states = {"NK-42": "cooking"}
        self.reads = 0
    def get_status(self, order_id):
        self.reads += 1
        return self.states[order_id]

class CachedStatus:
    def __init__(self, source, clock, ttl):
        if ttl <= 0:
            raise ValueError("ttl must be positive")
        self.source, self.clock, self.ttl = source, clock, ttl
        self.cache = {}
    def get_status(self, order_id):
        now = self.clock()
        cached = self.cache.get(order_id)
        if cached is not None and now < cached[0]:
            return cached[1]
        status = self.source.get_status(order_id)
        self.cache[order_id] = (now + self.ttl, status)
        return status
    def invalidate(self, order_id):
        self.cache.pop(order_id, None)

    cents: int

    right: object
    def evaluate(self, facts):

    right: object
    def evaluate(self, facts):
        return self.left.evaluate(facts) or self.right.evaluate(facts)

Read the example

The pool keys by recipe name and version, sharing a frozen specification with immutable ingredient tuples while rejecting conflicting content for an existing version. Three live lines retain two recipe specifications rather than three, avoiding one retained duplicate specification and its ingredient structure rather than merely interning a name string. Quantity, notes, and historical charged price remain on each line, so sharing does not merge customer choices.

What it costs / when to skip it

Pool lookups and retained entries have overhead, and savings depend on substantial repeated recipe data rather than a guaranteed byte count; separate small records are simpler for a tiny menu, with pool eviction needed for long-lived growth.

Do not confuse it with...

Singleton permits one instance of a class; Flyweight permits many shared instances, one per intrinsic recipe identity, while keeping extrinsic order data separate.

23. Singleton One instance with visible costs
Creational

Maya considers one shared default fee configuration after separating recipes from individual order prices. The earlier integer-cent fee calculation still needs predictable behavior in isolated tests and future catering branches.

What hurts now

Constructing settings at several call sites could create conflicting defaults, but hidden global settings could also leak changes between tests.

The small design move

Use __new__ to return one shared instance and expose a global accessor for that instance. Guard initialization so repeated construction does not overwrite settings, while explicitly limiting this non-thread-safe demo to one process.

Global settings accessor→Unique settings instance→Fee callers

Remember: One instance with visible costs

Python 3.10+ · standalone checkpoint
from types import SimpleNamespace

# One-process, non-thread-safe demonstration only.
class KitchenSettings:
    _instance = None
    def __new__(cls, fee_bps=500):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
    def __init__(self, fee_bps=500):
        if getattr(self, "_initialized", False):
            return  # First initialization wins; later arguments are ignored.
        self.fee_bps = fee_bps
        self._initialized = True

def settings():
    return KitchenSettings()

def fee_cents(subtotal_cents, config=None):
    if config is None:
        config = settings()
    return subtotal_cents * config.fee_bps // 10000

# Isolate this test's class-level state, then restore the previous instance.
saved = KitchenSettings._instance
try:
    KitchenSettings._instance = None
    first = KitchenSettings(500)
    second = KitchenSettings(900)
    assert first is second is settings()
    assert second.fee_bps == 500
    assert fee_cents(2000) == 100
    assert fee_cents(2000, SimpleNamespace(fee_bps=0)) == 0
    print(f"Same instance: {first is second}")
    print(f"Default fee cents: {fee_cents(2000)}")
    print(f"Injected fee cents: {fee_cents(2000, SimpleNamespace(fee_bps=0))}", end="")
finally:
    KitchenSettings._instance = saved
Expected output
Same instance: True
Default fee cents: 100
Injected fee cents: 0

Read the example

__new__ enforces identity on ordinary construction, while settings provides global access and the initialization guard prevents a second constructor call from resetting values. This demo is only one-process and non-thread-safe, not a cross-process uniqueness guarantee; its deliberate first-initialization-wins policy ignores later constructor arguments. The test restores class-level state in finally, and an explicitly injected configuration avoids the global dependency for fee tests.

What it costs / when to skip it

Global access hides dependencies, complicates state isolation, and needs additional design for threads or multiple processes; creating one ordinary settings object at startup and injecting it is usually simpler and safer.

Do not confuse it with...

Flyweight shares many immutable values by key; Singleton controls one class instance and provides a global access point, without making that instance immutable.

Try it before revealing

Pass a separate configuration with fee_bps set to 0 into fee_cents, as the injected example does; prefer that explicit dependency for branch-specific behavior.

# Composite and Decorator agree on a price() interface.
@dataclass(frozen=True)

    name: str

    def price(self):
        return self.cents

class Extra:
    dish: object
    cents: int

    def price(self):
        return self.dish.price() + self.cents

@dataclass(frozen=True)
class Bundle:
    children: tuple

    def price(self):
        return sum(child.price() for child in self.children)

    return 0

# Observer: readiness has independent listeners.
class ReadyEvents:
    def __init__(self):
        self.listeners = []

    def subscribe(self, listener):
        self.listeners.append(listener)

    def announce(self, order_id):
        for listener in tuple(self.listeners):
            listener(order_id)

# Facade: the counter uses one small entry point.
class KitchenApp:
    def __init__(self, events):
        self.events = events
        self.orders = {}

    def place_order(self, order_id, meal, fee_policy):
        if order_id in self.orders:
            raise ValueError("Order ID already used")
        subtotal = meal.price()
        charged = subtotal + fee_policy(subtotal)
        self.orders[order_id] = charged
        return charged

    def mark_ready(self, order_id):
        if order_id not in self.orders:
            raise KeyError(order_id)
        self.events.announce(order_id)

notifications = []
events = ReadyEvents()
events.subscribe(notifications.append)
app = KitchenApp(events)
family_lunch = Bundle((
    Extra(Dish("Soup", 700), 100),
    Dish("Bread", 200),
))

assert family_lunch.price() == 1000
charged = app.place_order("K-1", family_lunch, local_delivery)
assert charged == 1300
app.mark_ready("K-1")
assert notifications == ["K-1"]
print("K-1: 1300 cents; ready notification sent")
